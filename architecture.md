# Техническая архитектура проекта "MyNewAttemp Engine" (Версия 2.0)
> **Статус документа:** Утвержден. Действует с 15 октября 2026 года.
> **Стек технологий:** PHP 8+, JSON, Bootstrap 5, Apache (XAMPP). Внешние СУБД (SQL) и тяжелые JS-фреймворки запрещены.

---

## 1. Концепция изоляции контуров (Public / Private)

Проект жестко разделен на две независимые зоны для обеспечения безопасности данных, защиты исходного кода и стабильности путей веб-сервера.

### Карта каталогов проекта
```text
MyNewAttemp/
│
├── config.ini               # Глобальные тумблеры (IS_PRODUCTION, дебаг)
├── .gitignore               # Щит репозитория (уже зафиксирован в корне)
│
├── app/                     # ЗАКРЫТАЯ ЧАСТЬ (Private контур)
│   ├── config/
│   │   └── config.php       # Динамический вычислитель абсолютных путей
│   │
│   ├── core/                # Ядро системы
│   │   ├── auth.php         # Менеджер доступов на базе REMOTE_USER
│   │   └── logger.php       # Единый потоковый журнал логов
│   │
│   ├── controllers/         # Место для исполняемых PHP-классов
│   │   ├── AdminController.php
│   │   ├── ImportController.php
│   │   ├── CatalogController.php
│   │   └── OrderController.php
│   │
│   └── data/                # БАЗА ДАННЫХ (JSON-хранилище)
│       ├── products/        # Запчасти и аксессуары (registry.json)
│       ├── models/          # Бренды и модели техники (models.json)
│       ├── orders/          # Заказы в иерархии Год -> Месяц -> Дата
│       └── system/          # roles.json и ваш зафиксированный .htpasswd
│
└── public/                  # ПУБЛИЧНАЯ ЧАСТЬ (То, что видит Apache)
    │
    ├── assets/              # Статические ресурсы фронтенда
    │   ├── css/
    │   ├── js/
    │   └── vendor/          # Сюда позже распакуем Bootstrap 5 локально
    │
    ├── media/               # Медиа-хранилище фронтенда
    │   └── system/          # Логотипы и заглушки панели
    │
    └── manager/             # Шлюз управления
        ├── .htaccess        # Наш замок Apache (уже зафиксирован здесь)
        └── admin.php        # Чистая точка входа в интерфейс дашборда

```

### Правила изоляции:
1. Браузер клиента и DevTools имеют физический доступ **только к папке `public/`**.
2. Папка `app/` полностью отрезана от веб-доступа конфигурацией сервера (`403 Forbidden`). 
3. Запрещен любой хардкод путей дисков (вроде `C:/xampp/...`). Все пути бэкенда вычисляются динамически в `app/config/config.php` через `__DIR__` относительно корня бэкенда.

## 2. Логика Автономного Стек-Хранилища (PHP + JSON)

Данные хранятся в виде структурированных, валидных JSON-файлов в кодировке UTF-8. 

### Правило "Чистого JSON":
Любая запись на диск со стороны PHP-контроллеров обязана использовать флаги форматирования для обеспечения читаемости базы данных человеком через обычный текстовый редактор:
```php
file_put_contents($file, json_encode($data, JSON_PRETTY_PRINT | JSON_UNESCAPED_UNICODE));
```

### Структура архивных папок:
* **`data/products/`**: Содержит дерево категорий (`categories.json`) и плоский реестр товаров (`registry.json`).
* **`data/models/`**: Хранит справочники брендов (`brands.json`) и паспорта моделей устройств (`models.json`).
* **`data/orders/`**: Строгая временная иерархия **Год -> Месяц -> Дата.json**. Заказы за 15 октября 2026 года пишутся атомарно в файл `data/orders/2026/10/2026-10-15.json`, исключая перегрузку диска при поиске.

## 3. Архитектура Неубиваемой Совместимости: Концепция "Ключ — Замок"

Чтобы избавить проект от костылей ручной привязки («деталь А подходит к моделям 1, 2, 3...»), система использует **инвариантную параметрическую совместимость**. Связи между независимыми папками `products/` (товары) и `models/` (техника) вычисляются математически по физическим свойствам сопряжения деталей.

### Схема взаимодействия:
1. **Замок (Задается инженером в спецификации модели прибора):** Описывает физические параметры посадочного места конкретного рабочего узла техники.
2. **Ключ (Задается в паспорте товара при импорте детали):** Описывает точные физические размеры и свойства самой запчасти.
3. ** PHP-Сопряжение:** Если параметры Ключа полностью входят в параметры Замка — система автоматически объявляет деталь совместимой с устройством.

### Примеры узлов сопряжения по категориям техники:

#### Мясорубки:
* **Узел `knife_auger_grid` (Нож — Вал шнека — Решетка)**
  * *Параметры сопряжения:* Форма посадки (`square` / `hexagon`), Размер посадочного вала (мм), Номинальный внешний диаметр решетки (мм), Направление вращения (`right` / `left`).
* **Узел `auger_gearbox` (Хвостовик шнека — Предохранительная втулка — Редуктор)**
  * *Параметры сопряжения:* Тип хвостовика (`шлицы` / `лыска` / `квадрат`), Количество зубьев/шлицев, Диаметр вала (мм).
* **Узел `body_flange` (Горловина шнека — Корпус мясорубки)**
  * *Параметры сопряжения:* Диаметр посадочного фланца (мм), Тип фиксатора (`bayonet` / `screw`).

#### Пылесосы:
* **Узел `suction_tube` (Труба — Шланг — Насадка/Щетка)**
  * *Параметры сопряжения:* Номинальный диаметр стыка (32 мм / 35 мм / овал), Тип фиксации (`friction` (трение) / `clip` (защелка)), Способ сопряжения (`internal` / `external`).
* **Узел `dust_bag` (Рамка мешка — Пазы корпуса)**
  * *Параметры сопряжения:* Стандарт рамки пылесборника (`Type G`, `Type P`, `BBZ`, `универсальный`), Геометрические габариты пластикового фланца (мм).
* **Узел `filter_hepa` (Рамка HEPA фильтра — Посадочное гнездо)**
  * *Параметры сопряжения:* Точные габариты рамки (Длина х Ширина х Высота в мм), Наличие резинового уплотнительного бортика (`true` / `false`).

## 4. Регламент Транзакционного Импорта Товаров

Модуль импорта (`ImportController.php`) работает по принципу **атомарной транзакции**. Загрузка пакета данных (ZIP-архив с WebP-картинками и JSON-паспортом) либо выполняется на 100% успешно, либо полностью откатывается, не оставляя мусора в системе.

### Этапы работы конвейера импорта:
1. **Контроль доступа:** Проверка прав REMOTE_USER на выполнение действия `import_pipeline`.
2. **Валидация пакета:** Проверка целостности ZIP и сверка MIME-типа сервером Apache.
3. **Создание изолированного буфера:** Распаковка во временную папку `app/data/system/temp/import_[uniqid]/`. Процессы разных операторов изолированы друг от друга.
4. **Бинарная проверка ресурсов (Защита от инъекций):** Проверка WebP-картинок по Magic Numbers (`RIFF`...`WEBPVP8`). Скрипты, маскирующиеся под картинки, блокируются.
5. **Синтаксическая валидация паспорта:** Сверка JSON-структуры. Обязательно наличие полей `sku`, `name`, `price`, `category`, `parameters` (Ключи сопряжения).
6. **Генерация системного UUID:** Если товар импортируется впервые, ядро присваивает ему постоянный уникальный UUID. При повторном импорте (обновлении цен/остатков) UUID сохраняется неизменным, защищая историю заказов и жесткие связи.
7. **Фиксация (Commit):** Перенос проверенной графики в `public/media/products/[sku]/`, запись метаданных в `app/data/products/registry.json`.
8. **Очистка (Rollback / Cleanup):** Полное уничтожение временной папки буфера при любом исходе транзакции.

## 5. Регламент CSV-Документации Моделей (Шаблон Инженера)

Чтобы исключить человеческий фактор и двусмысленность (когда в описании прибора не указан его тип), инженеры заполняют спецификации строго по обновленному CSV-шаблону с выделенной шапкой метаданных и блоком «Замочков» совместимости.

### Структурный стандарт CSV:
```csv
#МЕТАДАННЫЕ_СИСТЕМЫ#;;;;
Бренд;Carrera;;;;
Модель;CRM564;;;;
Тип_техники;Мясорубка;;;;
Дата_спецификации;17.04.2025;;;;
;
#--- МАТРИЦА СОВМЕСТИМОСТИ (ЗАМОЧКИ) ---#;;;;
Узел_knife_auger_grid;Форма: квадрат; Размер_мм: 10; Номинальный_диаметр_решетки_mm: 62; Направление_вращения: правое
Узел_auger_gearbox;Форма: шлицы; Количество_шлицев: 12; Диаметр_вала_mm: 16;
;
#КОНЕЦ_МЕТАДАННЫХ#;;;;
Артикул;Кол-во;Наименование;Описание;Изображение
gr-362;1;решетка;;
pu-514;1;толкатель;;
kn-2658;1;нож;;
gr-523;-;решетка;;
```

### Логика обработки знака количества (`-`):
* Если количество указано как **целое число (>=1)**, бэкенд заносит деталь в массив `factory_assembly` (заводская базовая комплектация модели).
* Если количество указано как **минус или прочерк (`-`)**, бэкенд заносит деталь в массив `compatible_accessories` (конструктивно совместимые опциональные насадки или решетки, приобретаемые отдельно).
